# TSF 宿主回归

## Windows 11 兼容性验收

引擎管道使用同一登录 SID 的低完整性 ACL，拒绝网络客户端；服务端读取每条请求后以 identification 级别检查登录 SID、会话及 AppContainer 状态，再执行原有能力令牌鉴权。其他控制管道仍为中完整性。低完整性桌面宿主可连接，严格 AppContainer 的跨容器引擎访问尚不支持，不通过 Everyone 或 ALL APPLICATION PACKAGES 放宽系统边界。低完整性宿主使用前需由正常桌面进程初始化引擎及能力令牌。

新增原生回归覆盖候选 owner、IME_SHOW/HIDE/CHANGE 通知、停靠/浮动键盘避让、负坐标显示器、UIA 名称/选中状态和旧候选对象失效。Rust 回归以实际低完整性 token 打开命名管道，验证引擎允许访问而普通控制管道拒绝写入。

在 Windows 11 实机补充验证：

- 记事本、系统搜索、Edge 和 Electron 输入时，候选不激活、不抢焦点；关闭或最小化宿主后消失。
- 开启讲述人，检查候选逐项朗读、方向键选中播报、翻页后候选更新；输入框 A 切到 B 后，旧无障碍对象不能选中或提交 B 的候选。
- 使用系统触摸键盘输入拼音，检查中英文状态、前后翻页；普通 Unicode 粘贴保持原行为，不作为拼音二次处理。
- 停靠、浮动键盘显示/隐藏时，候选重新避让；100%/200% 跨屏及负坐标副屏下位置正确。
- ARM 系统在安装入口被拒绝；x64 系统的 64 位、32 位宿主均可加载对应 TIP。

自动化运行环境和 Windows 11 实机验收应分别记录，不能以 Windows 10 上的通过结果代替 Win11 现场验收。

本次改动涉及 `text_edit_sink.cpp`、`composition_sink.cpp`、`thread_mgr_sink.cpp`、
`key_sink.cpp` 及组合串提交／生命周期代码。文本编辑回调只使用只读锁检查；
删除预编辑和结束组合串通过异步读写编辑会话完成。清理持有原组合串对象，
不会把新焦点作为提交目标。宿主拒绝清理时记录诊断，不重发已经写入的文字。

自动回归见 `tsf-tip/tests/policy_tests.cpp` 的 `TestTsfHostFailureSequences`：
覆盖写入成功但结束失败、写入被拒绝、部分写入、同步终止重入、回调重复执行、
旧会话异步回调失效，以及光标／选择范围的边界和比较失败。

安装后在记事本、Word、浏览器 textarea／contenteditable、Electron 编辑框分别检查：

| 操作 | 预期 |
| --- | --- |
| 输入 `nihao`，点击同一输入框内组合串外的位置 | 旧候选消失，随后输入从新光标位置开始 |
| 将光标移到组合串内部或边界 | 保留当前组合串 |
| 拖动选择范围覆盖组合串之外的文字 | 结束旧会话，不删除宿主替换的文字 |
| 输入期间滚动编辑区 | 候选跟随组合串位置，不保留旧锚点 |
| 宿主脚本替换组合串文字或主动终止组合串 | 保留宿主文字，旧候选和旧任务失效 |
| 输入框 A 输入拼音后切到 B，再迅速切回 A | 不向 B 提交 A 的文字，旧清理不删除 A 的新组合串 |
| 输入期间 Alt+Tab、关闭弹窗或标签页 | 旧查询不能重新显示候选，新输入可正常开始 |
| 长按退格、快速连续按空格 | 每次实际按键最多处理一次，无重复上屏 |
| Shift 配合快捷键；按住 Shift 切换焦点后松开 | 快捷键正常，松键不误触发中英文切换 |

真实应用验收需安装后人工执行；策略测试不能替代宿主提供的 TSF 回调和布局行为。

## 发布前人工矩阵

每次触及 TSF 会话、候选布局、窗口缩放或提交回退时，记录 Windows 版本、安装器哈希、宿主版本、位数、显示缩放和结果。至少在 Windows 10 与 Windows 11 各覆盖记事本、Word、Chromium 文本框和 Electron 编辑框；游戏验证覆盖一个全屏 D3D 应用的聊天开关路径。多显示器回归包含 100%/200% 混合缩放、跨屏拖动和远程桌面连接变化。先执行上表的焦点切换与重复输入场景，再分别验证快速输入期间引擎退出、恢复与候选窗清理。

自动化部分由 `scripts/verify.ps1` 和仓库工作流覆盖 x64/x86 原生策略、配置及异步 I/O 回归。自动化通过不代表真实宿主矩阵通过；发布记录应分别填写自动化结果和现场宿主结果。
