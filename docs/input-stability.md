# 输入稳定性与验证基线

## 故障处理

引擎未就绪、查询超时或 IPC 断开时，按键检查放行新的输入，清空候选及拼音缓冲，并撤销旧查询和排队按键。后台候选结果处理也执行同样的检查；活动输入每 250 毫秒检查引擎状态，辅助进程存活每 2 秒检查一次。旧组合由原 TSF 上下文的编辑会话取消；取消尚未完成时不开始新组合。

自动恢复最多尝试 3 次，间隔分别为 1.5、3、6 秒。键盘轮询、辅助进程看门狗和瞬时 IPC 错误共用同一恢复预算。耗尽后保持键盘放行；恢复就绪或明确修改自动恢复开关才重置预算。游戏内遵守原有通知隐藏策略，可从托盘及诊断状态检查引擎故障。

## 输入结束

切英文、退出游戏聊天、TSF 上下文变化、键盘焦点丢失、宿主停用和实际配置重载调用 `EndInputSession`，统一失效焦点代次、查询序号、候选刷新和定位定时器、待处理学习通知及候选结果，并清空拼音及造词状态。宿主停用不再排入新的取消会话。宿主允许编辑时执行组合取消；失焦时异步取消仍绑定原组合代次。

## 排序测试基线

- 没有外部词库时也使用内置 8,105 常用字顺序，扩展字保留在尾部，验证 `xiong` 首屏包含“熊”且不包含“能”。
- 标准学习模式下，两字手动造词首次只观察，第二次确认后才提升。测试分别验证首次召回及确认后的热词前置，不移除重复确认策略。
- 简拼和混拼的冷扩展词降到尾部；最终整词补回及首屏救援后再次执行冷词排序，避免“虎皮鹦鹉”重新占据 `hpyw` 首屏。全拼仍可召回。
- 冷查询、限时提前返回和缓存回放共用最终候选整理；显式学习顺序在此阶段重新应用。

## 验证范围

Rust 库与设置程序测试、x64/x86 原生策略与配置测试、源码编码和安装器来源检查，以及两个安装包清单校验。不自动安装到宿主；真实游戏、浏览器及 Office 的故障注入和长时间运行仍需实际应用验证。
